# Flutter 版开发计划 (初版)

> 状态: 草案 v0.1 · 2026-11-14
> 目标: 用 Flutter 重写 file-sync-pro, 解决旧 Python 版的问题 (见 [旧实现分析](./summary-analysis-of-frozen-python-implementation.zh.md)), 优先跑通 macOS ↔ Android 的局域网文件同步.

## 1. 产品目标与范围

**核心能力**

1. 局域网设备发现与文件互访 (浏览、下载、上传).
2. 两台设备之间指定目录的**双向增量同步**, 支持预演 (dry run).
3. 明确的冲突处理: 不静默覆盖, 冲突可回看、可选择.
4. 可靠的基线语义: 中断可恢复, 不产生 "假装已同步" 或 "永远追不平" 的状态.

**平台优先级**

| 平台 | 优先级 | 说明 |
|---|---|---|
| macOS | P0 | 主力开发与验证平台, 第一个可用版本 |
| Android | P0 | 首个真实需求是 "电脑 ↔ 手机" |
| Windows | P1 | 第二台电脑, 在 macOS 上完成开发后到 Windows 机器上构建验证 |
| iOS | P2 (未来) | 保留工程骨架, 暂不投入 |

**本期不做**

- 公网/跨网段同步、云盘中转.
- 多人共享与权限体系.
- iOS 真机发布.
- 文件版本历史 (先只保留冲突副本).

## 3. 阶段任务

### M0 工程基座

- [x] `flutter create` 初始化 (macos / windows / android / ios), 包名 `com.likianta.file_sync_pro`.
- [x] 目录规范与分层 (见 §4), 空壳页面 + 主题.
- [ ] 基础依赖: 状态管理、路由、日志、本地存储、网络 (选型见 §5).
- [ ] 主题与设计 token (颜色/间距/圆角/字体), 深色模式.
- [ ] 应用数据目录约定 (配置、快照、日志、冲突副本).
- [ ] 开发脚本: `dart format`, `flutter analyze`, 测试命令写入 AGENTS.md 或 README.
- [ ] macOS: 窗口最小尺寸、标题、沙盒 entitlements (网络客户端/服务端、用户选择文件读写).

**验收**: `flutter run -d macos` 启动空壳应用; `flutter analyze` 无问题.

### M1 同步内核 (纯 Dart, 无 UI/网络)

优先级最高, 因为它决定正确性.

- [x] 清单模型:
  - `ManifestEntry { kind(file/dir), mtime, size, hash? }`
  - `Manifest { root, scannedAt, entries }`
  - `SyncState { base }`, 按同步对持久化为 JSON (版本号 + 迁移策略); 不再为两侧各存一份 base, 避免基线分裂.
- [x] 扫描器: 递归枚举、忽略规则 (gitignore 语义: glob、`!` 取反、目录尾 `/`)、可选哈希 (大小/mtime 快速路径).
- [x] diff/plan 引擎: 纯函数 `plan(base, a, b) -> List<Action>`.
  - 动作: create / update / delete / conflict (重命名先按 "删除 + 新增" 处理, move 优化放到 M6).
  - 双方都改时: 哈希相同 → 无需动作; 哈希不同 → 冲突, 不自动覆盖.
  - 支持 "mtime 变旧也算变更" (与旧版的关键差异).
- [x] apply 引擎:
  - 先写临时文件再原子 rename; 写后校验大小.
  - 保留 mtime; 目录创建/空目录清理.
  - 操作日志 (journal): 当前记录动作与错误, 自动恢复待后续实现.
  - 冲突副本按相对路径保存, 不覆盖同名.
- [x] 单元测试: 决策矩阵表驱动 (47 个用例).
- [x] 本地目录 A ↔ B 的端到端测试 (无需网络).

**验收**: 30+ 场景已覆盖 (新增/修改/删除/重命名/双方修改/仅改 mtime/空目录/忽略规则/冲突/中断暂未覆盖), 全部通过.

### M2 传输层与设备互访

- [ ] 设备发现: mDNS (`_filesync._tcp`) + 手动 IP 兜底; 展示设备名/平台/在线状态.
- [ ] 配对: 6 位配对码 → 持久化 token; 之后的请求带 token 校验.
- [ ] 协议 (MVP):
  - 控制面: HTTP JSON (`/info`, `/list`, `/manifest`, `/plan`, `/apply`).
  - 数据面: HTTP GET/PUT 流式传输, 支持 `Range` 断点续传, 传后校验.
  - 并发: 2–4 个并行传输, 可配置; 失败重试与超时.
- [ ] 文件互访 UI: 远端目录浏览、下载、上传、进度与取消.
- [x] **本机 ↔ 本机同步测试**: 以 `test/local_sync_test/alice` 与 `test/local_sync_test/bob` 作为固定夹具, 覆盖新增/修改/删除/重命名/双方修改/空目录/忽略规则等假想场景; 自动化测试先复制到临时目录再执行, 保证夹具本身不被修改.
- [ ] 安全: 仅监听局域网; 拒绝未配对请求; 不提供任意命令执行能力.

**验收**: 两台设备互访文件; 中断后恢复传输; 未配对设备无法访问; alice ↔ bob 的本地同步场景全部通过.

### M3 同步 MVP (macOS ↔ Android)

- [ ] 同步对 (sync pair) 配置: 本机目录 ↔ 远端目录、忽略规则、方向 (双向/单向).

## 4. 架构草案

```
lib/
├── main.dart
├── app/                 # App 壳: 路由、主题、本地化、启动流程
├── core/                # 通用能力: 结果类型、日志、错误、平台信息、路径
├── data/                # 本地持久化: 配置、快照、日志、冲突副本
├── features/
│   ├── devices/         # 设备发现、配对、设备列表
│   ├── browser/         # 远端文件浏览与传输
│   └── sync/            # 同步对、计划、执行、冲突
│       ├── domain/      # 纯 Dart: Manifest / Scanner / Planner / Applier
│       ├── application/ # 用例编排、状态机
│       └── presentation/# 页面与组件
└── transport/           # 协议、发现、HTTP/WS 客户端与服务端
```

原则:

- `features/sync/domain` 保持**纯函数、无 IO**, 便于测试;
- 平台差异收敛在 `core/platform` 与各 feature 的 `data` 层;
- UI 不直接做 IO, 通过 application 层用例驱动.

## 5. 关键技术决策 (默认方案, 可调整)

| 决策点 | 默认方案 | 理由 |
|---|---|---|
| 状态管理 | Riverpod | 可测试、依赖注入方便、社区成熟 |
| 路由 | go_router | 桌面多窗口/深链后续可扩展 |
| 清单变更判定 | size + mtime 快速筛选, 必要时哈希 | 修掉旧版 "mtime 单一判据" 的根因 |
| 哈希算法 | sha256 (MVP) → 可换 xxh3/blake3 | 先正确后提速 |
| 传输 | HTTP (dart:io / shelf) + 流式; WS 仅用于事件推送 | 简单、可调试、易做断点续传 |
| 发现 | mDNS + 手动 IP | 不依赖固定 IP |
| 认证 | 配对码换 token | 局域网内最小可用安全 |
| 本地存储 | JSON 快照 + 轻量设置存储 | 可读、易迁移; 大数据量再换 sqlite |
| 并发 | Isolate 扫描/哈希, 传输 2–4 并发 | 避免 UI 卡顿 |

> M0 结束前确认上述选型, 再开始 M1.

## 6. 平台要点

**macOS**

- 开发期关闭 App Sandbox 或配置 `com.apple.security.network.client/server` 与用户选择文件读写; 上架 App Store 需重新评估.
- 监听端口需允许入站连接 (防火墙提示).

**Android**

- 方案 A: SAF 目录授权 (`ACTION_OPEN_DOCUMENT_TREE`) — 合规、无需敏感权限, 但随机读写性能与 API 限制较多.
- 方案 B: `MANAGE_EXTERNAL_STORAGE` — 实现简单、性能好, 但应用商店受限; 个人使用可接受.
- MVP 建议先 B (快速验证), M4 再补 A.
- 后台运行必须前台服务; 长时间扫描需分片并响应取消.

**Windows**

- 优先复用 Dart 层; 只处理路径、锁文件、编码差异.
- 需在 Windows 机器上完成最终构建与验证.

**iOS**

- 文件系统沙盒严格, 只能同步应用容器或用户选择的目录; 后台调度受限.

## 7. 测试策略

1. **单元测试**: Planner 决策矩阵、忽略规则、路径规范化、清单序列化.
2. **属性测试**: 随机生成文件树与操作序列, 验证 `apply(plan(...))` 的不变量.
3. **集成测试**: 两个临时目录的本地同步; 模拟传输失败/中断.
4. **端到端手测清单**: macOS ↔ Android / Windows 的真机场景表.
5. **性能基准**: 1k / 10k / 100k 文件的扫描、diff、传输耗时.

## 9. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| Android 存储权限方案选择 | 影响 M3/M4 进度 | M2 期间做 SAF 原型验证 |

| Windows 构建环境 | M5 延期 | 提前在 Windows 上跑通空壳构建 |
| 大目录性能 | 体验差 | 增量扫描与清单分页, M6 专项 |
